# sagp pilot: per-gradient cost, fit diagnostics and the alpha table

**Provenance.** Generated 2026-09-08 by `--stage all` (7102 s active) on the author's M3
laptop (`CW52D2L07Q`, 8 cores) with XLA's default thread pool while other sessions were
running. The run used the module as of commit 380698f (before ruling R38): in the `fit`
section the two fits of each pair used different PRNG keys, so the "compile" line (-6.0 s for
product/lengthscale at n = 200) is not a compile time but a fit-to-fit difference, and the
`refit` table has no attempt-0 (`a0_`) columns. Everything else in the file (walls,
diagnostics, steps per iteration, acquisition walls, refit rates, the alpha table, the cost
stage) is valid.

Generated by `scripts/pilot_sagp.py` (plan task 11). Each section is written by its own stage and
carries the date, host and core count of the run that produced it, so sections may come from
different runs; `--stage all` refreshes all of them. Regenerate with

```
PYTHONPATH=. /opt/anaconda3/envs/saasbo/bin/python scripts/pilot_sagp.py --stage all
```

(on a laptop, under `caffeinate -di`: a sleeping machine does not advance `perf_counter`, so a
suspended run reports times that are wrong rather than merely late).

## Stage: alpha

Measured 2026-09-08 on `CW52D2L07Q`, `os.cpu_count()` = 8.

10000 draws of the prior-predictive active count #{i : theta_i > cutoff} at
D = 100, for the reference's rho scale and the amplitude cells' a^2 scale. Both priors are the
same half-Cauchy scale mixture, so the count depends on (alpha, cutoff) only through
cutoff / alpha and matching them fixes `ALPHA_AMPLITUDE` in closed form (plan D2); this table
is the numerical check that the whole count distribution matches, not only its median.

| prior scale | alpha | cutoff | median | q25 | q75 |
|---|---|---|---|---|---|
| reference (rho) | 0.1 | 0.1524 | 37 | 16 | 64 |
| amplitude (a^2) | 0.01312 | 0.02 | 37 | 17 | 65 |

Constants: `ELL_EPS` = 2.5613 (v(ELL_EPS) = ACTIVE_EPS = 0.02), `RHO_EPS` = 0.1524, `ALPHA_AMPLITUDE` = ALPHA_LENGTHSCALE * ACTIVE_EPS / RHO_EPS = 0.01312.

## Stage: cost

Measured 2026-09-08 on `CW52D2L07Q`, `os.cpu_count()` = 8.

Plan D8's run cost for one T = 200, D = 100 run, per cell:

```
t_fit  = 768 x steps x t_grad(n = 200)
cost   = 62 x t_fit x (1 + 1.67 r) + 180 x t_acq
```

`t_grad` is the grad stage's largest measured n; `steps` and `t_acq` are the fit stage's
measured `num_steps_mean` and acquisition wall; `r` is the refit stage's refit rate. The 62
is sum_{n=20}^{199} cost(n) / cost(200) over a run's 180 fits and the 1.67 is a doubled
warm-up refit's cost, both from the plan.

| cell | t_grad(n = 200) ms | steps/iter | t_fit min | r | t_acq s | core-hours per run |
|---|---|---|---|---|---|---|
| product/lengthscale | 4.32 | 52.6 | 2.91 | 0.30 | 13.2 | 5.17 |
| additive/amplitude | 44.6 | 15.3 | 8.75 | 0.00 | 62.8 | 12.2 |
| additive/lengthscale | 196 | 52.6 | 132 | 0.30 | 13.2 | 205 |
| product/amplitude | 133 | 52.6 | 89.9 | 0.30 | 13.2 | 140 |

additive/lengthscale, product/amplitude fall back to the reference cell's steps/iteration, acquisition
wall and refit rate wherever the fit and refit stages did not fit that cell themselves:
only two of the four are fitted, and steps/iteration is a property of the sampler's
adaptation rather than of the kernel's cost.
