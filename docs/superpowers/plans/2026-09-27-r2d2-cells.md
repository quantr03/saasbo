# R2-D2 prior family for the `sagp` 2 × 2: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the prior family a crossed factor of the study -- 2 (structure) × 2 (parameterization) × {half-Cauchy, R2-D2} -- by adding the R2-D2 prior to all four `sagp` cells and running the gated program the brief sets (prior-only study, cells, offline replay, in-loop pilot, full replicate), without changing one number the half-Cauchy cells or the three references produce.

**Architecture:** One bottom-of-stack module, `sagp/r2d2.py`, holds the prior: a loop-free Gaussian-copula map `z -> log F_Gamma(k)^-1(Phi(z))` tabulated from a verified Newton solver, and the two exact parameterizations (reference form, tied Gamma-Gamma form) behind one entry point, `sample_log_theta`. `sagp/gp.py` gains four `PyroModel` subclasses that override only the prior block, registered under two new prior strings, `amplitude_r2d2` and `lengthscale_r2d2`; the three places that dispatch on the prior string dispatch on the cell's declared `native_site` instead. The replay, the pilot and the replicate are study code on the public API (`experiments/`, `slurm/`, an analysis snapshot). One constant selects the parameterization and three hold its calibration, beside `ALPHA_AMPLITUDE`.

**Tech Stack:** unchanged -- `/opt/anaconda3/envs/saasbo/bin/python` (Python 3.11; jax 0.10.2, numpyro 0.21.0, botorch 0.18.1, torch 2.14.0, scipy 1.17.1, numpy 2.4.6); nothing is installed. Analysis snapshots keep their own venv (numpy, scipy, pandas, matplotlib), built by their `run_analysis.sbatch` on Triton, as `sagp_analysis/2026-09-12-1428/` does.

**Spec:** `docs/superpowers/specs/2026-09-27-r2d2-cells-brief.md` (verbatim). ## Review Focus

The five conditions the brief implies that no test in it exercises, most likely first; each has its test in the owning task.

1. **A replay against the wrong data.** A source run that is incomplete (`t > t_done`), resumed under another configuration (checkpoint hash ≠ manifest hash), missing row `t`, or whose `y[:t]` does not reproduce row `t`'s `y_mean`/`y_std` must be refused, never fitted on a shorter or different dataset. Tests in Task 8.
2. **A prior string reaching a string dispatch.** Any `cell[1] == "..."`, `.prior == "..."` or tuple comparison against a prior literal silently misroutes an R2-D2 cell (planning found three: `sagp/gp.py:710`, `sagp/readouts.py:232`, `:266`). Rule (e) in `tests/test_layering.py` forbids them in `sagp/` and `experiments/` (Task 5); `scripts/pilot_sagp.py:223` is outside that scope and half-Cauchy-only, and is named in D3.
3. **R2-D2 constants or form changed under a running study.** `config_hash` does not see module constants, so a resume after a constant changed, or reuse of pilot runs in the replicate, would splice two priors with no error. The analysis checks that every R2-D2 run's creation commit and every resume commit have identical blobs of `sagp/gp.py` and `sagp/r2d2.py` (Task 14), and Task 15 reuses the pilot runs only if that check passes against the replicate's launch commit.
4. **Extreme `z` and underflow.** The runtime map must be finite, monotone and finite-gradient for |z| up to 40; `rho` underflowing to exactly 0 makes `rho ** -0.5` (inside `kernel_additive_lengthscale`, and `1/sqrt` in the product-lengthscale path) a NaN gradient. The lengthscale R2-D2 block floors `log rho` at -450, which moves the law only where the prior has mass of about 1e-97 per coordinate (Task 6 test with `z = -40`). The floor is -450, not the planning value -700: below log rho ≈ -473 the derivative of `rho ** -0.5` itself overflows (ledger ruling R21).
5. **The fixed-noise path.** With `fixed_noise` set there is no `noise` site; every R2-D2 cell must trace, fit and predict on that path, and the R2 readout must take the noise from `FittedGP.noises()`, not from a site. Tests in Tasks 5 and 6.

## 1. Decisions

**D1 -- Parameterization, behind one interface.** Both exact parameterizations from the scouting live in `sagp/r2d2.py` behind one function, and the cells never branch on which is active:

```python
# sagp/r2d2.py -- imports jax and numpyro only; nothing from sagp
FORMS: tuple[str, ...] = ("reference", "tied")
SAMPLED_SITES: dict[str, tuple[str, ...]] = {
    "reference": ("r2d2_R2", "r2d2_z_lam"),   # Beta site on R2, copula shares
    "tied": ("r2d2_z_xi", "r2d2_z_lam"),      # every site N(0, 1)
}

def log_gamma_icdf_newton(z: ArrayLike, k: float) -> Array:
    """y = log F_Gamma(k,1)^-1(Phi(z)) by Newton in log space: the verified reference solver.

    `icdf2.py::log_gamma_icdf_from_normal` hardened: documented branches (lower on log gammainc with
    the small-x series below x = 1e-6, upper on log gammaincc), a convergence check in place of the
    unjustified 80 steps, custom_jvp dy/dz = phi(z) / (x f_k(x)). Off the hot path: it builds the
    runtime table and is the accuracy reference in the tests.
    """

def log_gamma_icdf(z: ArrayLike, k: float) -> Array:
    """The runtime map: the same y, loop-free, from a table cached per shape k."""

def sample_reference(dim: int, *, a: float, b: float, k: float) -> Array:
    """log theta: r2d2_R2 ~ Beta(a, b), r2d2_z_lam ~ N(0, I); y = log_gamma_icdf(z_lam, k),
    log theta = log R2 - log1p(-R2) + y - logsumexp(y). Any (a, b, k)."""

def sample_tied(dim: int, *, b: float, k: float) -> Array:
    """log theta = log_gamma_icdf(z_lam, k) - log_gamma_icdf(z_xi, b): the paper's a = k * dim."""

def sample_log_theta(dim: int, *, form: str, k: float, b: float, a: float | None = None) -> Array:
    """The one entry point: theta_i = omega * phi_i, R2 ~ Beta(a, b), phi ~ Dir(k, ..., k).

    `a` None is the paper's tie a = k * dim (valid in both forms); "tied" with any other `a` raises
    ValueError. Creates the sampled sites of `SAMPLED_SITES[form]` only; the caller names the
    deterministic native site. Returns (dim,) log theta.
    """
```

Switching: each R2-D2 model reads the constant `R2D2_FORM` (in `gp.py`) through its class attribute `r2d2_form`, and `Cell.sites` is built from `r2d2.SAMPLED_SITES[R2D2_FORM]`, so changing the form is one constant plus its three calibration constants and no class or registry edit.

*Recommendation:* the reference (untied) form calibrated on the count quartiles, if it passes stage 0 at that point; the tied form at the paper's b = 0.5, median-matched, as the fallback. *Reasons:* (1) the brief's own confound -- only the untied form can match the half-Cauchy count distribution beyond its median (§0: the tied form reaches at best (22, 36, 56) against (17, 37, 64), the untied form (14, 37, 60) with a proper R2 prior); (2) the tied calibrated global prior puts 0.3 % of its mass below R2 = 0.6 while a standardized target implies R2 at most about 0.5 (§0), a prior-data conflict on the one coordinate every a_sq shares; (3) it is the supervisor's own free-(a, α) form, and what the paper's tie buys (its tail and origin rates, the Gibbs sampler) does not transfer to GP component variances (2026-09-21 note, reason 5). This reverses the brief's expected default; G0 decides with the stage-0 data.

*Required in both forms, not a choice:* the runtime map is loop-free (§0: the prototype costs 12-15 times a likelihood gradient on CPU, and nests while-loops that are worse on GPU). Recommended construction, since k and b are constants of a cell: a quintic Hermite table of y_k on z ∈ [-38, 36] built once per shape from the Newton solver (outside any trace: NumPy/SciPy or `jax.ensure_compile_time_eval`, so that a first call inside `jit` does not stage the solver's while-loops), with y' = φ(z)/(x f_k(x)) and y'' = y'·(-z - (k - x)·y') in closed form (x = e^y); below -38 the small-x asymptote y = (log Φ(z) + lgamma(k + 1))/k, whose neglected term, about x/(k + 1), is below 1e-15 there for every shape up to 21 (at z = -8 it is still 0.08 for k = 20.93, which is why the table reaches -38); above 36 the tangent line at 36, so the map stays strictly increasing and C¹ everywhere (the edge is 36, not higher, because past z ≈ 37 the upper tail Q = 1 - Φ(z) falls below 1e-300 and the solver's `gammaincc` branch underflows; the prior mass beyond 36 is about 1e-284, ledger ruling R3). The upper range is wide because a dominant coordinate's posterior can sit at z ≈ 6 or beyond. Tabulating a residual such as k·y - log Φ(z) instead of y keeps the error uniform in k (y itself reaches -1.5·10^5 at k = 0.005). Acceptance is in Task 2, as a relative error |Δy| ≤ 1e-10·max(1, |y|).

**D2 -- Calibration rule.** *Matched:* the prior distribution of N = #{i : a_sq_i > ACTIVE_EPS} at D = 100, against the half-Cauchy cells' (quartiles (17, 37, 64), mean 41.6; `test_alpha_matches_reference_count` states 16-17, 37, 64).

- Tied: one knob, k, at the paper's b = 0.5 -- the median only. Residual: quartiles (28-29, 36-37, 44-45), an interquartile range of 16 against 47. Freeing b buys little ((22, 36, 56) at b = 0.05).
- Reference form: three knobs (a, b, k) -- the median exactly, and max(|q25 - q25_HC|, |q75 - q75_HC|) minimized over the proper region a ≥ 0.5, b ≥ 0.5 (which excludes the U-shaped R2 priors that reach ±3 only with sd(log ω) ≈ 20) and k ≤ 1/2, ties broken by the continuous residual; a sensitivity point with k ≤ 1 is reported beside it (ledger ruling R15). Without a bound on k the objective has no minimizer -- it keeps falling toward uniform shares (k, a, b → ∞), a dense prior with a random global scale, which the Design brief's premise that every cell's prior is sparse excludes -- and k ≤ 1/2 is the R2-D2 paper's regime of a spike at the origin (Theorem 4). Planning residual about 3 at (1.5, 0.76, 0.47); stage 0's Tier D refines the optimum and reports the exact residual.

The residual goes into the calibration test, the constants' comment and the thesis table caption, because it confounds prior family with the *dispersion* of sparsity (the median is matched).

*Transport to rho:* `rho_i = R2D2_RHO_SCALE * omega * phi_i`, `R2D2_RHO_SCALE = RHO_EPS / ACTIVE_EPS = 7.6218`. Then #{rho_i > RHO_EPS} = #{ω φ_i > ACTIVE_EPS} draw for draw, so the two R2-D2 columns share one calibration and one residual, exactly as `ALPHA_AMPLITUDE` makes the two half-Cauchy columns share one: the residual confounds prior family only, never parameterization within R2-D2. Stage 0's rho-scale variant is then this sampler with a constant offset on the output, verified by an identity instead of separate runs (Q4). R2 has no meaning on the rho scale -- ω is a global inverse-squared-lengthscale scale there -- and the lengthscale R2-D2 cells get no R2 readout.

*Constants* (`gp.py`, after `ALPHA_AMPLITUDE` at :232): `R2D2_FORM`, `R2D2_K` (per-coordinate Dirichlet concentration k = α/D, the paper's a_π), `R2D2_A` (None when tied), `R2D2_B`, `R2D2_RHO_SCALE`, with a comment that cites the Tier D table and states the matched statistics and the residual. *Test:* `test_r2d2_calibration_matches_reference_count` beside `test_alpha_matches_reference_count` (Task 6), NumPy only.

**D5 -- Model classes.** Every R2-D2 class is a subclass of its half-Cauchy twin; two of them define the prior block, the other two are method-resolution compositions with no body:

```python
# sagp/gp.py, after ProductAmplitudePyroModel (:444-448)
class AdditiveAmplitudeR2D2PyroModel(AdditiveAmplitudePyroModel):
    """additive/amplitude with the R2-D2 prior on a_sq: `sample_amplitudes` is the only difference."""

    alpha: float = R2D2_K              # CellGP sets it from Cell.alpha_default (k, per coordinate)
    r2d2_form: str = R2D2_FORM
    r2d2_a: float | None = R2D2_A
    r2d2_b: float = R2D2_B

    def sample_amplitudes(self, dim: int) -> Array:
        log_theta = r2d2.sample_log_theta(
            dim, form=self.r2d2_form, k=self.alpha, b=self.r2d2_b, a=self.r2d2_a
        )
        return numpyro.deterministic("a_sq", jnp.exp(log_theta))


class ProductAmplitudeR2D2PyroModel(AdditiveAmplitudeR2D2PyroModel, ProductAmplitudePyroModel):
    """product/amplitude with the R2-D2 prior: the prior block from the first base, the product
    kernels (`_jax_kernel`, `_torch_kernel`) from the second."""


class ProductLengthscaleR2D2PyroModel(ProductLengthscalePyroModel):
    """SAASBO's kernel with the R2-D2 prior on rho; `sample` stays BoTorch's."""

    alpha: float = R2D2_K
    r2d2_form: str = R2D2_FORM
    r2d2_a: float | None = R2D2_A
    r2d2_b: float = R2D2_B

    def sample_inv_length_sq(self, dim: int) -> tuple[Array, Array]:
        log_theta = r2d2.sample_log_theta(
            dim, form=self.r2d2_form, k=self.alpha, b=self.r2d2_b, a=self.r2d2_a
        )
        # Floor: rho exactly 0 would make rho ** -0.5 a NaN gradient (Review Focus 4).
        log_rho = jnp.maximum(jnp.log(R2D2_RHO_SCALE) + log_theta, -450.0)  # ruling R21
        inv_length_sq = numpyro.deterministic("kernel_inv_length_sq", jnp.exp(log_rho))
        lengthscale = numpyro.deterministic("lengthscale", 1.0 / jnp.sqrt(inv_length_sq))
        return inv_length_sq, lengthscale

    def postprocess_mcmc_samples(self, mcmc_samples: dict[str, Array]) -> dict[str, torch.Tensor]:
        """Every site as torch, `lengthscale` recomputed from the retained rho as BoTorch does."""
        mcmc_samples["lengthscale"] = 1.0 / jnp.sqrt(mcmc_samples["kernel_inv_length_sq"])
        return {site: torch.tensor(np.asarray(draws), dtype=self.train_X.dtype,
                                   device=self.train_X.device)
                for site, draws in mcmc_samples.items()}


class AdditiveLengthscaleR2D2PyroModel(ProductLengthscaleR2D2PyroModel, AdditiveLengthscalePyroModel):
    """additive/lengthscale with the R2-D2 prior: the prior block and postprocessing from the first
    base, `sample` and `load_mcmc_samples` (the additive kernel) from the second."""
```

The brief suggests the product variants by attribute swap; composing with the twin gives the amplitude column the same two swapped attributes and makes every R2-D2 class a subclass of its twin, which the twin test relies on. In the lengthscale column a swap is not available at all: `AdditiveLengthscalePyroModel` overrides `sample` and `load_mcmc_samples` rather than class attributes, and the composition reuses both without copying them. The method resolution is pinned by a test (Task 6): for each R2-D2 class, `sample`, `load_mcmc_samples`, `get_dummy_mcmc_samples`, `sample_mean`, `sample_noise` and, where the twin has them, `sample_ell`, `_jax_kernel`, `_torch_kernel` are the twin's own objects. `ProductLengthscalePyroModel`'s own `postprocess_mcmc_samples` reads `kernel_tausq` and `_kernel_inv_length_sq`, which the R2-D2 block does not have, hence the override. Registry entries:

**D8 -- Readouts.**

R2 is a per-fit scalar, so it is not a `coords.csv` column: `sagp.readouts` gains `r2d2_r2(a_sq) = S/(1 + S)` (what the Beta prior is on) and `first_order_r2(a_sq, noise) = S/(S + σ²)` (the fitted model's first-order R², S = Σ_i a_sq_i per draw — exact for the additive amplitude cells; for product/amplitude, whose signal variance is Π_i(1 + a_sq_i) - 1 ≥ S, the model's first-order R² is S/(Π_i(1 + a_sq_i) - 1 + σ²), which the analysis computes there; ruling R20); the replay writes their medians per fit and the analysis recomputes both from every amplitude cell's npz (the stored `noise` is BoTorch's raw draw, which prediction clamps at 1e-4; a fixed-noise run stores no `noise` and takes its value from the manifest). `first_order_r2` is the misspecification detector of Q4 (≈ 1 - γ when interaction variance goes to the noise); the thesis must say that under the uncoupled prior the Beta prior is on S/(1 + S), not on the data's first-order R² (Q7).
