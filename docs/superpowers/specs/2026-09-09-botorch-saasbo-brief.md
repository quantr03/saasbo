# Brief: move `sagp` from the vendored SAASBO code path to BoTorch's SAASBO, on Papenmeier's protocol (2026-09-09)

You are planning (not yet implementing) a migration of the thesis's model and optimization code. Read this whole brief, the files it names and the two repositories it names, then produce an implementation plan. Do not write implementation code until I approve the plan.

## What I want

Replace the vendored SAASBO reference code path — `saasgp.py`, `saasbo.py`, `util.py` (github.com/martinjankowiak/saasbo @ 4af4a8e) and everything in `sagp/` that copies or imports it — with BoTorch's SAASBO: the `PyroModel` / `SaasFullyBayesianSingleTaskGP` framework fit by `fit_fully_bayesian_model_nuts`'s scheme, predicting through `GaussianMixturePosterior`, with BoTorch's LogEI averaged over the posterior samples and maximized by `optimize_acqf`. That is the inference scheme Papenmeier et al. (2025) use for SAASBO in their benchmarks (BoTorch's implementation, run directly), and their BO loop is the protocol to copy around it: analytic LogEI, `optimize_acqf` with RAASP sampling, a refit from scratch every iteration. Hvarfner et al. (2024) run the same BoTorch SAASBO through Ax with cost shortcuts (a reduced NUTS budget, a refit every 4 iterations) and a different acquisition (qLogNEI); none of that is adopted. Hvarfner's settings appear below only so the plan can tell the two apart. Where Papenmeier's code makes a choice, the plan follows it; where it is silent (the SAASBO model itself), BoTorch's defaults are the scheme.

The four thesis cells ({additive, product} structure × {amplitude, lengthscale} prior) must all live inside that framework, so that, as today, they differ in nothing but the kernel/prior block. The product/lengthscale cell must *be* BoTorch's `SaasPyroModel` (a test pins its log density to BoTorch's), not a copy of it.

Everything that is not the model, the sampler, the prediction or the acquisition must keep working unchanged: `synthobj`, `sagp.bo.run_bo`'s adapter interface, the readouts and their meaning, `experiments/` (run directory, manifest, samples npz, checkpoint/resume, CLI `python -m experiments.run_bo`), the layering rules.

## Reference facts (verified; the plan builds on them, not on recollection)

**BoTorch 0.18.1.** `fit_fully_bayesian_model_nuts(model, max_tree_depth=6, warmup_steps=512, num_samples=256, thinning=16, disable_progbar=False, jit_compile=False, seed=0)`: `model.train()`; NumPyro `NUTS(model.pyro_model.sample, dense_mass=True, max_tree_depth=…)`; `MCMC(num_warmup, num_samples)`; `mcmc.run(jax.random.PRNGKey(seed))`; `model.pyro_model.postprocess_mcmc_samples(mcmc.get_samples())`; thin `[::thinning]`; `model.load_mcmc_samples(...)`; `model.eval()`. The `MCMC` object — its un-thinned draws and `get_extra_fields()` — is discarded. `PyroModel.set_inputs` stores `train_X_jax`/`train_Y_jax`; `sample_noise` = `1e-4 + Gamma(0.9, 10)` unless `train_Yvar` is given; `sample_mean` = `Normal(0, 1)`. `MaternPyroModel.sample`: outputscale, mean, noise, lengthscale, JAX `matern52_kernel`, `sample_observations`. `SaasPyroModel`: outputscale `Gamma(2, 0.15)`; `sample_lengthscale(dim, alpha=0.1)` = `kernel_tausq ~ HalfCauchy(alpha)`, `_kernel_inv_length_sq ~ HalfCauchy(ones(dim))`, deterministic `kernel_inv_length_sq`, `lengthscale = 1/sqrt(·)`; `postprocess_mcmc_samples` **deletes** `kernel_tausq` and `_kernel_inv_length_sq`; `load_mcmc_samples` builds `ConstantMean`, `ScaleKernel(MaternKernel(nu=2.5, ard))`, `GaussianLikelihood` with the 1e-4 noise floor, all batched over S. `SaasFullyBayesianSingleTaskGP(train_X, train_Y, train_Yvar=None, outcome_transform=None, input_transform=None, use_input_warping=False)` expects X in [0, 1]^d and standardized Y; `_is_fully_bayesian = _is_ensemble = True`; `posterior(X, observation_noise=…)` returns a `GaussianMixturePosterior` over the S draws (`MCMC_DIM`). `average_over_ensemble_models` reduces a log acquisition over S by `logmeanexp` and any other by the mean — so analytic `LogExpectedImprovement(model, best_f)` on a fully Bayesian model computes exactly what `sagp.bo.log_ei` computes today. `optimize_acqf(acq_function, bounds, q, num_restarts, raw_samples, options)`; `gen_batch_initial_conditions` honours `options["sample_around_best"]`, `sample_around_best_sigma` (default 1e-3), `sample_around_best_subset_sigma` (1e-1), `sample_around_best_prob_perturb` (default min(1, 20/d) for d ≥ 20) — this is Papenmeier's RAASP. `get_fitted_map_saas_model` exists for a MAP-SAAS variant (not asked for).

**Hvarfner et al. 2024** (context only — not the protocol adopted here; §5, App. A.1): SAASBO "run through Ax"; "the lower-budget variant outlined in App. A1 of Eriksson & Jankowiak (2021)", i.e. (N_warmup, N_post, L) = (128, 128, 8); at most 500 evaluations; "the model is retrained once every 4 iterations". Their vanilla-BO loop (repo `configs/`): Ax `BOTORCH_MODULAR`, qLogNEI with `prune_baseline`, `optimize_acqf` with `raw_samples 512`, `num_restarts 4`, `sample_around_best: true`, `sample_around_best_sigma 0.1`, `maxiter 300`, `batch_limit 64`; Sobol initial design of ⌈3√D⌉ points; noise 0.01 on the synthetic tasks; the DSP prior on an **RBF** kernel by default (`benchmarking/gp_priors.py`, `model=default`), Matérn only in variants. Their README notes BoTorch ≥ 0.12 ships the DSP prior as `SingleTaskGP`'s default.

**Papenmeier et al. 2025** (§5, App. B; repo `understanding-hdbo-code`, pinned botorch 0.9.5): SAASBO baseline run through BoTorch for 500 iterations, runs beyond 72 h terminated; their reference loop standardizes y every iteration, builds a fresh `SingleTaskGP` (Matérn-5/2 ARD in a `ScaleKernel` with `Gamma(2, 0.15)` outputscale, noise prior Gamma(1.1, 0.05)) each iteration, refits from scratch (`refit_every = 1` reproduces the paper), uses analytic `LogExpectedImprovement(best_f = y_norm.max())`, `optimize_acqf(q=1, num_restarts=5, raw_samples=512, options={"batch_limit": 1, "sample_around_best": True, "sample_around_best_sigma": 0.001})`, and queries a uniform random point when the fit or the maximizer raises. App. B: of 4m raw samples, 2m are Sobol, m perturb every coordinate of the top 5 % with σ = 1e-3, m perturb each coordinate with probability 20/d; starts are Boltzmann-selected (Ament et al.).

**Eriksson & Jankowiak 2021** App. A.1: 768 = 512 + 256 NUTS steps, thinned to L = 16, tree depth 6, one chain; reducing to (128, 128, 8) costs "a relatively marginal drop in performance". ## Decisions the plan must make (a recommendation and a reason for each)

1. **Where the four cells live.** Recommend: four `PyroModel` subclasses in `sagp/gp.py`, the product/lengthscale one being `SaasPyroModel` itself (subclassed only to keep the sites the readouts need), the other three overriding `sample()` with the existing NumPyro site structure and the existing JAX kernels (`kernel_additive_amplitude` etc. already take JAX arrays, so the log density ports nearly verbatim), plus `load_mcmc_samples` returning (mean, covar, likelihood) modules batched over S. One `AbstractFullyBayesianSingleTaskGP` subclass per cell, or one class parameterized by `Cell` — say which and why.
2. **Priors.** Adopt BoTorch's SAAS priors where the reference's differed: constant mean `Normal(0, 1)` (was zero mean), outputscale `Gamma(2, 0.15)` (was `LogNormal(0, 10)`), noise `1e-4 + Gamma(0.9, 10)` (was `LogNormal(0, 10)`), `alpha = 0.1`. The amplitude cells keep `a_sq_i = tausq · lam_i` at `ALPHA_AMPLITUDE`, no outputscale, `kernel_ell ~ LogNormal(0, 1.5)`, and take BoTorch's mean and noise priors. State how `fixed_noise` maps onto `train_Yvar` (a constant column) and what the 1e-4 floor does to the noiseless out-of-family checks. Confirm in the plan (with the argument, not a simulation) that the α calibration and `shares_from_amplitudes` survive.
3. **Sampler.** BoTorch's scheme: NumPyro NUTS, `dense_mass=True` (the one sampler difference from the vendored reference — adopt it, it is the scheme), tree depth 6, 512/256/16, one fresh chain per fit, seeded per iteration from `iteration_rngs(seed, t)` (BoTorch takes an int seed; derive it, do not reuse `PRNGKey(0)`). Because BoTorch discards the `MCMC` object, write `sagp.gp._run_nuts` as a line-for-line copy of `fit_fully_bayesian_model_nuts` that returns the sampler, then postprocess, thin and `load_mcmc_samples` ourselves; pin by test that with the same seed and model our copy's loaded hyperparameters equal BoTorch's function's, bit for bit. Keep `NUTSConfig` as the single budget object. Refit from scratch every iteration (Papenmeier's protocol, `refit_every = 1` in their code); do not add a refit-cadence knob — Hvarfner's every-4 is a cost shortcut the study does not take.
4. **Diagnostics.** Unchanged gate (`diagnose` on the un-thinned log draws, divergences from `extra_fields`), fed by the copied fit. Site names: keep `kernel_tausq`, `_kernel_inv_length_sq`, `kernel_inv_length_sq`, `_a_sq`, `a_sq`, `kernel_ell` in `FittedGP.samples` (own `postprocess_mcmc_samples`, since BoTorch's deletes two of them); map BoTorch's `noise`, `outputscale`, `mean` onto what `readouts` and `diagnostics` expect, or rename there — say which, and keep the npz schema in `runlog` stable or version it.
5. **Prediction.** `FittedGP.posterior(X_test) -> (S, n_test)` mean and noisy variance stays the interface for `sagp.bo`, `sagp.readouts` and `experiments`; implement it on the BoTorch model's `posterior(X, observation_noise=True)`. This requires torch implementations of the three centered kernels as batched `gpytorch.kernels.Kernel` subclasses (64-node Gauss–Legendre `v(ℓ)`, `kbar`, normalized and unnormalized additive sums, the product-of-(1 + a² k̄) form), with `forward(x1, x2, diag=…)` and lengthscale/amplitude parameters of batch shape (S,). The JAX kernels stay as the log-density side and as the oracle the torch kernels are tested against (1e-10). Say how `alphas()` (K⁻¹y per draw) is obtained from GPyTorch's prediction strategy or recomputed, and what the memory profile at 200 training points, D = 100, 512 + RAASP candidates is.
6. **Acquisition.** Analytic `LogExpectedImprovement(model, best_f = max z)`, Papenmeier's choice — q = 1, deterministic, and on the ensemble it is `logmeanexp` of per-draw log EI, i.e. today's `log_ei`. No `qLogNEI` option: one acquisition, as the design requires. Since BoTorch maximizes, `standardize` stops negating and `run_bo`'s `y_target = min(z)` becomes `best_f = max(z)`; state every place the sign flip reaches (readouts do not depend on it; the checkpoint/csv columns store `y`, not `z`).
7. **Acquisition maximizer.** Replace `optimize_ei` with `optimize_acqf(q=1, num_restarts, raw_samples, options={"sample_around_best": True, "sample_around_best_sigma": …, "batch_limit": …, "maxiter": …})`, seeded from `iteration_rngs` through `torch.manual_seed` (`raw_samples` are drawn from torch's Sobol; find where and pin it). Papenmeier's numbers, fixed: `num_restarts=5`, `raw_samples=512`, `sample_around_best_sigma=1e-3`, BoTorch's default `prob_perturb`, `batch_limit=1` (say whether a larger `batch_limit` changes anything but speed; if not, pick the fast one and record why). `RunConfig` gains these fields, hashed, and drops `num_init_candidates`/`num_restarts_ei`. Failure policy unchanged: one retry, then a seeded Sobol point and an `excluded` row.
8. **MAP references.** Replace the JAX `fit_map` with Papenmeier's `dsp` method verbatim (`understanding-hdbo-code/src/understanding_hdbo/model.py` and `fit.py`): BoTorch `SingleTaskGP`, Matérn-5/2 ARD in a `ScaleKernel` with the `Gamma(2, 0.15)` outputscale prior, `LogNormalPrior(√2 + log d/2, √3)` on the lengthscales initialized at the prior mode, `GaussianLikelihood` with the Gamma(1.1, 0.05) noise prior and `noiseless=False` (the study's targets are noisy), fit by their `fit_mll` (`fit_gpytorch_mll` with the Adam fallback), wrapped to the same `FittedGP` interface at S = 1; the oracle as the same model behind a `FilterFeatures` input transform on the true active columns, so `optimize_acqf` still searches [0, 1]^D. This settles the kernel family — Matérn-5/2, as `references.py` already documents; note BoTorch's `SingleTaskGP` default is RBF, so the covar module is passed explicitly. It also changes the DSP reference's priors from the current transcription (no outputscale, LogNormal(−4, 1) noise): record the change and re-target `tests/test_sagp_references.py`.
9. **The loop.** Keep `sagp.bo.run_bo` and its adapters (`surrogate(X, z, key) -> FittedGP`, `propose(fitted, best_f, rngs, t) -> (x, value)`); keep `initial_design` on scipy's scrambled Sobol (already seeded and tested; Papenmeier's torch `SobolEngine` is the same construction with a different scrambling stream, and nothing in the scheme depends on which). Papenmeier standardizes with torch's `y.std()` (ddof = 1); `sagp.gp.standardize` uses ddof = 0. Recommend keeping ddof 0 — the readouts' share mapping assumes unit sample variance exactly, and the difference is a factor (n − 1)/n on the targets that is no part of the inference scheme — and record the deviation. Everything torch runs in float64 on CPU (`torch.set_default_dtype(torch.float64)` at `sagp` import, beside `numpyro.enable_x64()`); say how thread counts are pinned for SLURM (`torch.set_num_threads`, and the JAX/XLA flags already in place).
10. **The vendored reference and its tests.** Recommend deleting `saasgp.py`, `saasbo.py`, `util.py`, `tests/test_bo_reference.py`, the `bit_for_bit` tests and `chunk_vmap` uses, in one final commit after the replacement reference test (below) is green — `git log` keeps them.
